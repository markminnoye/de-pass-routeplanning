Broncontract: `docs/superpowers/specs/2026-09-16-hybride-optimalisatie-design.md` §1–3, §Foutafhandeling, §Testen (offline/datapack).
Werkdir: repo-root op branch `wp2-datapakket-offline`. TDD verplicht (RED → GREEN). Geen WP3-solver, geen WP5-skill-herschrijving, geen `data geocode` (WP6).

## Global constraints

- Resolutie datamap: `--data <pad>` > env `BUSROUTES_DATA_DIR` > default `docs/samples/`.
- `--samples` blijft als alias van `--data` en print één deprecatie-melding op stderr.
- Datapakket-layout: verplicht `school.json`, `students.json`, `buses.json`; optioneel `pickup_points.json`; matrix in `<data>/matrix/<opties-digest>/<lat,lon>.json` (zelfde cellen-structuur als nu `.cache/tomtom/cells/`).
- `load_data_pack` leest het pakket; `load_samples` blijft de 3-tuple `(school, students, buses)` teruggeven (bestaande callers/tests niet breken) en delegeert intern naar `load_data_pack`.
- Ontbrekend verplicht bestand → `ScenarioError` met pad en verwachte layout; nooit stil falen.
- `TomTomClient` krijgt `cells_dir: Path | None = None`. Als weggelaten: huidige gedrag `cache_dir / "cells"` (unit-tests). CLI geeft `cells_dir = <data>/matrix`.
- `Settings` krijgt `data_dir`.
- Plugin-kopie: na elke wijziging in `busroutes/` `uv run python scripts/build_plugin.py` draaien zodat `tests/test_build_plugin.py::test_check_passes_on_this_repo` groen blijft.
- DoD na elke task: `uv run ruff check . && uv run ruff format --check . && uv run pytest` groen.
- Commit op branch `wp2-datapakket-offline`. Geen force-push, geen amend van andermans commits.

## Task 2: OfflineClient

TDD in `tests/test_offline.py`. Nieuw bestand `busroutes/offline.py`.

`OfflineClient(cells_dir: Path)` implementeert `GeoClient`:

- `usage = Usage()` met nullen.
- `route(points, depart_at)`: per opeenvolgend paar een `RouteLeg`:
  - `travel_time_s` = cel `a→b` (zelfde key als TomTom: `f"{lat:.6f},{lon:.6f}"`, zelfde options-digest-subdir als `TomTomClient._cells_path` — reuse `_point_key` / `_digest(MATRIX_OPTIONS)` uit `tomtom.py`, niet dupliceren als import lukt).
  - `length_m = round(haversine_m(a, b) * OFFLINE_ROAD_FACTOR)` met `OFFLINE_ROAD_FACTOR = 1.3`.
  - `points = [a, b]` (rechte lijn).
  - `depart_at` wordt genegeerd.
- `matrix(origins, destinations)`: alleen cellen lezen, nooit netwerk/fetch. Zelfde 2D-int-return als `TomTomClient.matrix`.
- Ontbrekende cel → `OfflineError` (nieuwe exception in `offline.py`) met het **aantal** ontbrekende paren en de tekst `busroutes data fetch-matrix --dry-run`. Geen fallback naar haversine.
- Lege `cells_dir` / ontbrekend paar: fail fast.

Tests bouwen een mini-matrix op schijf (één origin-json zoals de echte cache) in `tmp_path`. Geen TomTom-key, geen netwerk.

- legs.travel_time_s == de celwaarde
- length_m == round(haversine * 1.3)
- ontbrekend paar → `OfflineError` die het fetch-commando noemt
- `matrix()` geeft de cel, haalt niets op
- `usage.transactions == 0`

Plugin sync, ruff, pytest, commit.

## Task 3: evaluate --offline, metrics, map, compare

TDD. CLI + output. `evaluate --offline` mag **geen** `TOMTOM_API_KEY` nodig hebben.

### CLI

- `evaluate` krijgt `--offline` (flag) en `--data` (Path). `--samples` blijft; als de gebruiker `--samples` meegeeft (niet via default), print deprecatie op stderr en behandel het als `--data`.
- Datamap: `resolve_data_dir(args.data, samples_if_explicit, env)`.
- `--offline`: bouw `OfflineClient(data_dir / "matrix")`, niet `TomTomClient`. `load_settings(require_key=False)` of equivalent: referentiedatum blijft verplicht; `api_key` mag leeg.
- Zonder `--offline`: huidige `TomTomClient`, maar geef `cells_dir=data_dir/"matrix"` mee zodat online en offline dezelfde matrix delen.
- Overpass-overlay mag blijven (bestaande waarschuwing bij fail); geen TomTom-call.

### metrics.json

In `ScenarioResult.to_dict()` onder `settings`:

- `"mode": "offline" | "tomtom"`
- bij offline ook `"km_estimated": true`

Bepaal `mode` vanuit de client (bijv. `isinstance(client, OfflineClient)` of een veld op `ScenarioResult`/`Settings`). Bestaande unit-tests die `to_dict()` checken op exacte keys: voeg `mode` toe; default voor `FakeGeoClient` is `"tomtom"` (niet-offline).

`docs/samples/expected/*.metrics.json` bevat géén `mode` vandaag. `tests/test_regression.py` doet `assert actual == expected`. Voeg `"mode": "tomtom"` toe aan de drie expected-bestanden (en `"km_estimated"` niet). Geen andere cijfers wijzigen.

### map.html

Als `mode == "offline"`: zichtbare banner met exact (of duidelijk equivalent, Nederlandstalig):

`Offline-schatting: tijden uit de matrix, rechte lijnen, km geschat`

Km-label in de samenvattingstabel mag "(geschat)" tonen. Geen TomTom-polylines nodig: de client levert al rechte lijnen.

### compare

Kolom **Modus** (waarde `offline` / `tomtom`). Als de tabel zowel offline als tomtom bevat: extra zin onder de tabel dat de modi gemengd zijn (cijfers niet 1-op-1 vergelijkbaar).

## Task 4: `busroutes data` (status, fetch-matrix, add-points)

TDD in `tests/test_datapack.py` (uitbreiden). Nieuw `busroutes/datapack.py` voor de logica; CLI-wiring in `busroutes/cli.py`.

### Punten van een pakket

Alle matrixpunten = school + alle leerlingen + alle opstapplaatsen + bus-starts die niet samenvallen met school (zelfde `_point_key`-collaps als TomTom).

### `data status`

Geen TomTom-key. Telt: leerlingen, opstapplaatsen, bussen, aanwezige vs ontbrekende matrixparen (N×N over unieke punten). Raming om te vervolledigen via bestaande `plan_blocks` + `matrix_transactions`. Stdout menselijk leesbaar; ontbrekende paren > 0 is geen fout (exit 0).

### `data fetch-matrix [--dry-run]`

Haalt alle ontbrekende paren via `TomTomClient.matrix` (die al `plan_blocks` gebruikt). `cells_dir = <data>/matrix`. `--dry-run`: geen key nodig, print de raming (`usage_report(..., dry_run=True)`), schrijft niets. Zonder `--dry-run`: key verplicht (bestaande `ConfigError`).

### `data add-points <json>`

Invoer: JSON-lijst `[{"id"?: "...", "lat": ..., "lon": ..., "zone"?: "...", "kind": "student" | "pickup_point", "name"?: "..."}]`. Zonder `id`: genereer een id (`uuid4` hex of `s`/`pp-` + uuid, stabiel genoeg; niet het adres).

Voor elk punt: `snap_to_street` (op `TomTomClient`; als snap `None` teruggeeft: oorspronkelijk punt gebruiken en waarschuwen op stderr). Schrijf daarna atomisch naar `students.json` of `pickup_points.json` (hergebruik `_write_json` uit `tomtom.py` — importeer of til `_write_json` naar een gedeelde helper als import-cycli dreigen; geen copy-paste van de atomic-write).

Daarna: matrix vullen **enkel voor de nieuwe rijen en kolommen** (niet de hele NxN opnieuw). Test met een Fake-client:

- Breid `FakeGeoClient` in `tests/conftest.py` uit met `snap_to_street(point) -> point` (identiteit) zodat add-points in tests geen netwerk doet.
- Injecteer die client in de datapack-functie (dependency injection, niet monkeypatch van TomTomClient-class tenzij onvermijdelijk).
- Eén nieuw punt bij P bestaande unieke punten: `matrix_calls` dekt de ontbrekende rij+kolom, niet de rest. Tel de gevraagde cellen: in de orde `2*P` tot `2*P+1` (self-cel mag).

### CLI

Subparser `data` met subcommando's `status`, `fetch-matrix`, `add-points`. Deelt `--data` / `--samples`-alias. Fouten: `ScenarioError` / `ConfigError` / `TomTomError` / `OfflineError` → exit 1 via bestaande `main()`.

- `fetch-matrix --dry-run` zonder key, exit 0.
- `add-points` schrijft student, snap aangeroepen, matrix alleen nieuwe rij/kolom.
